# Domain Docs

## Layout

This repository uses a single-context layout:

- CONTEXT.md at the repository root: domain vocabulary.
- docs/adr/: architecture decision records.

## Before exploring

Read CONTEXT.md and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. The domain-modeling skill
creates them when terminology or decisions are resolved.

Continue following AGENTS.md's requirement to read the relevant
specifications in HotShop_Architecture.md.

## Vocabulary

Use the terms defined in CONTEXT.md when naming domain concepts in issues,
proposals, hypotheses, and tests.

If a needed concept is missing, check existing project terminology and
note genuine gaps for domain-modeling.

## Decision conflicts

Explicitly identify any existing ADR that a proposal contradicts and
explain why the decision should be reconsidered.
